The question, for number theory

Would Codeforces put the tag `number theory` on this problem?

Yes: The intended solution relies on properties of integers.

No: Integers are only quantities to add, compare or count.

Adding the solution

Dev macro F1: 0.729 both. Test: 0.737 without, 0.751 with.

Jev is TypeSafe's model, pinned at version 1.13.0. It does not write text: it reads a state, here the problem's statement and, for jev-statement-code, its solution, and answers each question it is given with a probability. Each request asks eight Noul questions, one per focus tag, in one call. Every question carries the same convention, that Codeforces tags name the ideas of the intended solution and that a problem often has several, the same question, would Codeforces put this tag on this problem, and the tag's own criteria: a definition of what counts as yes with examples it includes, and of what counts as no with examples it excludes. Shown here is number theory: properties of integers count; an answer printed modulo a large prime only to keep it small does not. The definitions were written from Codeforces conventions, without reading a dev problem or answer, and frozen. Nothing else is learned. The answer is a probability by name only: the per-tag thresholds, chosen on dev out-of-fold scores and ranging from 0.335 to 0.895 for jev-statement-code, decide, not 0.5. On dev, adding the solution changes nothing measurable: 0.729 macro F1 either way, against 0.732 for descode2tag-json, the best on dev. On test, jev-statement scores 0.737 and jev-statement-code 0.751, reported and not used to choose. jev-statement-code is the CLI default because it is about five times faster than descode2tag-json, 0.26 s against 1.21 s, for about thirteen cents per thousand problems. The frozen scores come from the committed answers; a new call is a new sample, so live scores can drift slightly.
