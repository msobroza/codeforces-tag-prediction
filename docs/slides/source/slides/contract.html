class TaggingMethod(Protocol):            # every method, any kind

    @property

    def name(self) -> str: ...            # its key in METHODS

    @property

    def tags(self) -> tuple[str, ...]: ...  # its output columns

    def predict(self, raw_problems: pd.DataFrame) -> pd.DataFrame: ...

    def save(self, folder: Path) -> None: ...   # data files only

class ScoreMethod(TaggingMethod, Protocol):     # kind "score"

The contract every tagging method follows, simplified from methods/__init__.py. Both protocols are runtime-checkable, so the tests can check a method with isinstance. A TaggingMethod has a read-only name, its key in the registry, the tags it outputs, a predict that turns raw problems into 0/1 tags, and a save that writes its own data files. A score method, such as TF-IDF, the ModernBERT bags, F2LLM or Jev, also exposes the scores its per-tag thresholds are applied to. Each method is one line of the METHODS registry: the module that loads it, its kind, the packages and dependency groups it needs, and whether it calls a paid API. save_method writes method.json and the method's files; load_method reads method.json and imports the module the registry names, which is how the CLI and the MLflow wrapper load a method. And the contract is executable: every method's tests call check_tagging_method, which checks the output shapes, types and tag vocabulary, that the labels or extra columns change nothing, that one problem at a time gives the same as a batch, that saving and reloading gives the same output, exactly or within the score tolerance the method declares, that the folder holds only data, and that loading and predicting in a fresh interpreter imports neither MLflow, Optuna nor an LLM provider's SDK.
