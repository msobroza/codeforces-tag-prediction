Command line

One entry point, codeforces-tags, for every method

List

codeforces-tags methods

Every method, its dev and test F1, its needs.

Predict

codeforces-tags predict sample_42.json

codeforces-tags predict problems/ --method tfidf

Default jev-statement-code; tfidf runs offline.

Evaluate

codeforces-tags evaluate --method tfidf --out report/

codeforces-tags evaluate my_labelled_problems/

Per-tag precision, recall, F1. Test part by default.

Train and freeze

python -m codeforces_tags.tuning run --trials 200

python -m codeforces_tags.tuning freeze

python -m codeforces_tags.methods.<package> freeze

python -m codeforces_tags.methods.<package> verify

Tune on dev, freeze once; verify re-derives it.

Prefix each command with uv run; an API method also needs its group, its key and --max-cost-usd.

The CLI is one entry point, codeforces-tags, also reachable as python -m codeforces_tags. methods lists what is frozen and what each method needs. predict takes one sample file or a folder of them and prints one JSON line of focus tags per problem; the default is jev-statement-code, the method chosen on dev, and tfidf is the free offline fallback. evaluate scores a method on the test part of the frozen split by default, or on any folder of labelled samples, and writes report.json and CSV tables. Training is per method: the TF-IDF tuning study, then freeze, which scores dev out of fold and test once; every other method has the same freeze and verify commands in its own package.
