How the TF-IDF method is built, simplified from the repository. Step one: a single scikit-learn Pipeline takes raw problems: its first step is the project's preprocessing, then the two TF-IDF feature blocks, then one linear SVM per tag. Because preprocessing lives inside the pipeline, the exact same object is used to train, to verify and to predict from the command line with --method tfidf. Step two: CrossFittedTagThresholds wraps the pipeline: it clones and fits it on four dev folds at a time to score the fifth, chooses each tag's threshold on those out-of-fold scores, then refits on all of dev; the result is saved with skops. Step three: the run record fingerprints what the result came from, the git commit, the dataset and split hashes, the environment and the settings, and log_method logs it once per recipe, in its own MLflow run, through a models-from-code wrapper, with its input signature, pinned requirements and parameters, then the dev and test metrics on the logged model. The freeze command refuses to write anything unless the new fit reproduces the study's out-of-fold F1 per tag exactly, its thresholds, and the pinned test macro F1; verify refits and re-derives the predictions, scores and method folder, and checks the run record's recipe.
