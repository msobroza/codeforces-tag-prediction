Top lane: what happens once. The data is read and split, each method is tuned on dev out of fold only, then frozen: dev predictions out of fold, the test set scored once. A verify command re-derives every frozen file, MLflow mirrors it, and the CLI serves it. Bottom lane: one prediction with the TF-IDF model. The raw problem goes through the same preprocessing as in training, because it is the first step of the saved pipeline. Two TF-IDF blocks: word unigrams and bigrams of the statement with its notes, 43,354 features, and regex tokens of the code, 2,354 features weighted 0.22. One linear SVM per tag scores the problem, and each tag's score is compared with its own threshold, chosen on dev out of fold. About 7 ms once loaded. The study tried sample I/O cue features too; they lowered the out-of-fold F1, so the chosen model leaves them out.
