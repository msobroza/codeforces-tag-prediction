Serving in practice

One command to try a method, four to check it step by step

Try it  model server, MLflow UI and Streamlit app in one terminal, all stopped on Ctrl-C

uv run --group app python -m codeforces_tags.serving up --method f2llm_late_fusion

Checks everything first and says what is missing  ·  --build builds the image  ·  --local without Docker  ·  --device gpu on the GPU

Step by step, with tfidf

Build

uv run python -m codeforces_tags.serving build --method tfidf

Run

METHOD=tfidf docker compose -f deploy/docker-compose.yml --profile cpu up --wait

Check

uv run python -m codeforces_tags.serving smoke --method tfidf

Ask

uv run --group app streamlit run apps/streamlit_app.py

The Streamlit app asking f2llm_late_fusion, served on the CPU: a typed problem, 1.31 s round trip

One command tries a method: serving up starts its model server, the MLflow UI and the Streamlit app in one terminal, opens the app in a browser, and stops all three on Ctrl-C. It checks everything before it starts anything and says what is missing; --build builds the method's image first, --local serves it without Docker, and --device gpu runs it on the GPU. Step by step, four commands serve tfidf on a laptop. build packages the frozen method and builds its image, tagged with the git commit; it refuses uncommitted inputs. docker compose starts it on localhost, CPU profile. smoke sends 20 test problems, one per request, and checks the answers against the frozen predictions. The Streamlit app predicts a test problem or one you type, shows each tag's score against its threshold, and links to the method's run and prompt versions in the MLflow UI, which another command serves. The response holds each focus tag as 0 or 1 and, for a score method, its score and threshold. The screenshot is the app on f2llm_late_fusion, the dense-embedding method: a typed Euler totient problem, predicted math and number theory, in 1.31 s round trip on the CPU. Under compose's GPU profile, the same method answered the 20 test problems at 0.148 s at the median and 0.262 s at the slowest, against 3.40 s and 8.21 s on the CPU. Kubernetes and SageMaker commands are in the repository's docs; SageMaker is written and tested offline, not yet run.
