# The command line runs jev-statement-code by default, a choice of the user

`codeforces-tags predict` and `codeforces-tags evaluate` run `config.CLI_DEFAULT_METHOD`, `jev-statement-code`, unless `--method` names another registered method. The user chose it among the frozen methods that [ADR 0004](0004-tagging-method-framework.md) makes eligible (frozen, not `dev_in_sample`, the slowest problem of its `latency.csv` under `config.LATENCY_BUDGET_S`), on its dev out-of-fold macro F1 and on what a prediction costs a user in time and money, never on a test score, so [ADR 0001](0001-model-selection-protocol.md) holds. ADR 0004's rule still decides which methods are eligible, and names the eligible method with the best dev out-of-fold macro F1: `codeforces-tags methods` lists both, in its `eligible`, `best_dev` and `default` columns, so a default that is not the rule's choice shows.

The two differ. The ten registered methods are frozen and eligible, and their dev out-of-fold macro F1 are: `descode2tag-json` 0.7319, `jev-statement-code` 0.7293, `jev-statement` 0.7289, `descode2tag-text` 0.7061, `tfidf` 0.6629, `modernbert_lora` 0.6611, `modernbert_base_full` 0.6530, `code2tag-json` 0.6514, `code2tag-text` 0.6421 and `label_prior` 0.1485. ADR 0004's rule names `descode2tag-json`, the zero-shot method that reads the statement, the notes and the solution and answers a JSON object, ahead of `jev-statement-code` by 0.0025; the default stays `jev-statement-code`, the user's choice.

The reason is latency, not cost. The committed `latency.csv` files, 50 timed live requests each, give `jev-statement-code` 0.260 s for one problem at the median and 0.570 s at the slowest, against 1.213 s and 3.648 s for `descode2tag-json`: Jev is 4.7 times faster at the median and 6.4 times at the slowest problem. A request costs about the same: $0.000133 on average for Jev (3,172 input tokens) and $0.000130 for `descode2tag-json` (1,201 input tokens), so Jev is about 2% dearer, and the 994 test problems cost about $0.13 with either. Each prediction is one paid request: to TypeSafe's API for Jev ([ADR 0007](0007-api-score-methods-share-the-llm-toolkit.md)), to OpenAI's for `descode2tag-json` ([ADR 0003](0003-api-methods-are-fixed-reference-models.md)).

## Considered options

- **ADR 0004's rule alone**: the default would be whichever eligible method leads on dev, by any margin: `descode2tag-json`, ahead by 0.0025 of dev macro F1, for a prediction 4.7 times slower at the median and no cheaper. It needs the `llm` dependency group and `OPENAI_API_KEY`.
- **`tfidf`**: it runs offline and for free, with no dependency group and no key, and its slowest problem takes 0.010 s once loaded (0.898 s), but its dev macro F1 is 0.0664 lower. It is `config.CLI_OFFLINE_METHOD`, the method every failure of the command line names.
- **`jev-statement`**: the same eight questions without the solution, at 0.7289 on dev (0.0004 lower) and $0.000116 a request. ADR 0007 concludes on dev whether the solution helps, and the default follows that comparison.
- **Falling back on `tfidf` when the default cannot run**: a user would get another method's tags without being told. The command line fails instead, with one line that names every unmet need and `--method tfidf`.

## Consequences

- A user without the `llm-typesafe` dependency group or `TYPESAFE_API_KEY` gets one line on stderr that names both, with the command that brings them (`uv run --group llm-typesafe --env-file FILE codeforces-tags ...`), and `--method tfidf`; nothing is loaded and no request is sent. A zero-shot method asked without the `llm` group or `OPENAI_API_KEY` fails the same way.
- `PROBLEM.md`'s ten seconds are for one prediction. ADR 0004 counts the slowest problem once the method is loaded (`max_s`), but a fresh `codeforces-tags predict` loads it first: `methods` lists both together as `cold_s` (the interpreter's start and imports aside), 0.573 s for `jev-statement-code`, 0.907 s for `tfidf` and 3.648 s for `descode2tag-json`, while the ModernBERT methods, eligible all the same, take 26.686 s and 10.836 s. A single `predict` with the default method takes 1.5 to 1.6 s wall clock, `uv run` included, and 3.8 s on the first run of a new environment (five live requests in all); with `tfidf`, 2.3 s.
- One prediction is one paid request (about $0.0001), sent without a cap; more requests need `--max-cost-usd` (`config.CLI_UNCAPPED_REQUESTS`). An `evaluate` of the test part sends 994 new requests, about $0.13, whose answers are new samples of Jev: its score can differ from the frozen test macro F1 (0.7515), which `codeforces-tags methods` lists, computed from the committed answers files.
- The default is not ADR 0004's choice, and `methods` shows it: `best_dev` names `descode2tag-json` and `default` names `jev-statement-code`. Notebooks 05, 06 and 08 say that the CLI's method is chosen on dev macro F1 alone (ADR 0004): that is the rule's `best_dev`, which notebook 05 finds in `descode2tag-json`, not the default, which this ADR sets.
